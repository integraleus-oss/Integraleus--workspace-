# Safe Repository Cleanup

## Procedure

1. Inspect the branch, upstream divergence, worktree status, repository size, and filesystem capacity; write a pre-cleanup snapshot with the Git HEAD and timestamp, completing the step when the original boundary is reproducible.
2. Classify every candidate as durable source, durable evidence/state, generated output, backup/migration remnant, or ambiguous; for mixed directories, compare tracked and ignored paths and archive only individually proven derived outputs rather than trusting the directory name or moving the whole tree. Leave durable and ambiguous paths untouched, and when a semantic batch contains no proven disposable targets, record that result and proceed without creating an unnecessary archive, completing the step when the cleanup list contains only proven temporary or generated files or is explicitly empty.
3. Write an exact target manifest before moving files; validate regular files and record symlinks separately with their exact link targets, then byte-compare the combined manifest path set with the intended tracked or scoped path set, completing the step when counts and paths match without dereferencing links.
4. For a generated environment such as a tracked virtualenv, record an exact dependency lock and prove that a clean replacement installs, passes its dependency check, and imports the required packages before removing the original. Archive targets outside the repository while preserving workspace-relative paths and symlinks; calculate SHA-256 values before and after the move, extract the archive into an isolated directory, compare every regular-file hash and symlink target, and run the same smoke checks on the restored copy, completing the step only when recreation and restoration both pass.
5. Record archive location, payload size, target count, restoration instructions, and the post-cleanup worktree boundary; retain the archive until the owner separately approves disposal, completing the step when restoration can be performed from the evidence alone.
6. Treat staged inbound/outbound media, sent deliverables, delivery evidence, message queues, notification records, SQLite data, and delivery state as the messaging boundary rather than generated clutter; keep them out of repository cleanup unless separately scoped and approved, never replay or resend messages as a cleanup side effect, and complete the step when evidence confirms those systems and artifacts were not mutated.
7. Commit only semantically reviewed batches; for application source, inspect structure and dependencies, scan candidate files for secret-shaped material without printing values, and run the smallest meaningful tests plus smoke check before committing. Keep maintenance, memory/state, skills, runtime history, and application source in separate commits, completing the step when each commit has a narrow purpose and verification evidence.
8. After multiple archival batches, run one aggregate closeout: verify every repository manifest against its external archive, confirm every archived source path is absent, total exact file counts and payload bytes, and index the batch commits, archive locations, restoration paths, retained boundaries, and deferred work; commit the closeout separately, completing the step when the whole cleanup can be audited and restored from one index.
9. Before pushing a long local-only range, verify the remote tip without updating refs, then audit divergence, linearity/merges, changed-path concentration, unique blob volume and large objects, high-confidence secret signatures without printing matched values, committed queue/outbox fixtures by schema and field names only, range-wide whitespace, and Git connectivity. Validate every dirty worktree separately with checks matched to its contents, and distinguish committed-range evidence from uncommitted state: a passing isolated test that needs an untracked fixture diagnoses the dependency but does not make the worktree reproducible or push-ready. Separate confirmed blockers from explained false positives, fail closed when required tests are not self-contained, and require explicit scope approval before changing operational state or delivery artifacts, completing the step when the owner has a concise push/no-push verdict, exact review targets, and an exact audited commit boundary.
10. Before an authorized history rewrite, resolve exact path rules to blob IDs and affected refs, distinguish current-tree cleanup from historical reachability, and verify whether tags or remote-tracking refs contain the targets. Create and test-clone a hashed all-refs bundle before filtering; run the rewrite only in an isolated mirror with a pinned filtering tool while leaving the original dirty worktree and refs untouched. Verify tip-tree equivalence, target-path and target-blob absence, Git connectivity, and the full pre-push audit, then require separate approvals to replace local refs and to force-push with an exact lease, completing the step when rollback is proven and the sanitized mirror is independently auditable.

## Stop Conditions

Stop before moving a path when its ownership, retention value, symlink status, or relation to a queue/message system is uncertain. Stop after any hash mismatch or unreadable archive and preserve both available copies for investigation.

11. Before replacing rewritten refs that have dirty worktrees, preserve each worktree independently: record its source HEAD and NUL-safe status/path manifests, capture staged and unstaged tracked changes as separate full-index binary patches, archive untracked files with symlinks preserved, and hash the payload. Test-extract the archive and verify every file hash and symlink target; then clone the sanitized mirror into a separate migration directory, check out the matching sanitized ref, apply the index patch before the worktree patch, extract untracked files, and compare the complete changed-path union and contents against the source. Run `git diff --check` and Git connectivity checks, record source and sanitized boundaries, and leave original refs, worktrees, remotes, and push/delivery state untouched until separately authorized, completing the step when all migrated dirty states are independently reproducible and equivalent.

12. When the owner authorizes local ref replacement, revalidate the exact old and sanitized commit IDs and compare every old-to-new tree-change path with the current staged, unstaged, and untracked path union; stop on any overlap. For a checked-out dirty branch, move to the sanitized commit with `git reset --keep` rather than changing the ref alone, so the index and worktree follow intentional rewritten-tree deletions while unrelated dirty state remains intact; verify the resulting ref, dirty path/content equivalence, filtered-path absence, unchanged remote configuration, and rollback bundle. Detect files modified after the preservation snapshot and capture a supplemental post-replacement snapshot with isolated restore verification before declaring completion, completing the step when all authorized refs and current dirty state are reproducible without any push, replay, resend, prune, or garbage collection.

13. After local ref replacement, prepare only the publication branch: partition dirty paths into narrow semantic batches, restore accidental or whitespace-only edits, and keep backups plus notification/outbox artifacts explicitly unstaged. Replace cross-task test dependencies with tracked fixtures in the owning test suite, prove the original branch-specific counts and the publication branch's complete suites, commit each reviewed batch separately, and audit the final closeout commit rather than the pre-closeout tip, completing the step when only declared exclusions remain dirty and no push, replay, or resend occurred.
