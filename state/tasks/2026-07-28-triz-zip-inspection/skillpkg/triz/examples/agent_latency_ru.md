# Пример (эвристический режим): глубина рассуждений агента ↔ латентность

**Запрос пользователя:** «Мой LLM-агент должен глубоко рассуждать — многошаговые цепочки, самопроверка, обращения к инструментам. Но пользователи жалуются на задержку ответа. Урезаю рассуждения — падает качество. Как быть?»

**Режим:** софт/агентные системы → эвристический (`resources/software_ai_systems.md`). Матрица не применяется; все решения помечены `Source: heuristic-analogy`.

---

## Шаг 1. Ситуация → мини-задача

- Система: диалоговый агент. Главная функция: **выдавать ответ пользователю** (не «рассуждать» — рассуждение лишь способ).
- Нежелательный эффект: время до ответа велико.
- Мини-задача: всё остаётся как есть (глубина рассуждения сохраняется), но задержка для пользователя исчезает.

## Шаг 2. ИКР

**Ответ появляется у пользователя сразу, при этом рассуждение выполнено в полном объёме — сама система находит время и место для рассуждения, не занимая время ожидания пользователя.**

Формулировка сразу подсказывает: конфликт не в объёме рассуждения, а в том, что оно занимает именно тот интервал, в котором пользователь ждёт.

## Шаг 3. Противоречия

- ТП-1: если рассуждать глубоко, качество высокое, но ожидание недопустимо велико.
- ТП-2: если рассуждать коротко, ожидание мало, но качество недопустимо падает.
- **ФП: рассуждение должно быть долгим (для качества) и коротким (для пользователя).** Дожали до ФП — работаем разделением.

## Шаг 4. Разделение противоречивых свойств

**Во времени** (`Source: separation-2`):
- Рассуждать ДО вопроса: предвычисление по предсказуемым запросам, прогрев контекста, заготовка планов (перевод приёма №10 «предварительное действие»).
- Рассуждать ПОСЛЕ первого ответа: выдать быстрый ответ сразу и продолжить уточнение фоном, с правкой ответа при необходимости (приём №16 «частичное или избыточное действие» + №21 «проскок»).

**По условию** (`Source: separation-по-условию`):
- Глубина как функция сложности: лёгкий маршрутизатор оценивает запрос; простое → быстрый путь без цепочек, сложное → полный конвейер с честным индикатором прогресса (приём №15 «динамичность», №3 «местное качество» — разные модели на разных участках).

**Системный переход 1в — части ↔ целое** (`Source: separation-5`):
- Каждый под-агент рассуждает коротко и параллельно, ансамбль в сумме рассуждает глубоко: конвейер декомпозиция → параллельные короткие ветки → быстрая сборка (приём №1 «дробление» + №5 «объединение», парный приём «дробление—объединение», `Source: paired-principle-1`).

**Обратить время ожидания в ресурс** (шаг «Ресурсы» + приём №22 «обратить вред в пользу»):
- Стриминг промежуточных шагов: пользователь видит ход рассуждения — воспринимаемая задержка падает при той же фактической; ожидание превращается в канал доверия и раннюю точку коррекции («не то ищешь — смотри в X»).

## Шаг 5. Ревизия ресурсов

Уже есть в системе: история диалога (кэш планов по повторяющимся запросам), простои между запросами (фоновая консолидация памяти агента — приём №41 «использование пауз», `Source: extended-principle-41`), собственные прошлые ответы (дистилляция частых цепочек в короткие правила).

## Шаг 6. Итог

| Вариант | Механизм | Близость к ИКР | Источник |
|---|---|---|---|
| Быстрый ответ сразу + фоновое дорассуждение с правкой | разделение во времени | высокая: ожидание ≈ 0, глубина сохранена; цена — механизм правки ответа | heuristic-analogy |
| Маршрутизатор глубины по сложности запроса | разделение по условию | высокая для типового трафика; цена — сам маршрутизатор | heuristic-analogy |
| Параллельные короткие под-агенты + сборка | системный переход (части↔целое) | средняя: латентность ≈ самой долгой ветке; растёт сложность оркестрации | heuristic-analogy |
| Стриминг хода рассуждения | вред → польза (воспринимаемое время) | дополняющий к любому из вариантов | heuristic-analogy |

Компромисс («рассуждать поменьше») не понадобился: все варианты сохраняют полную глубину рассуждения.

**Валидированные альтернативы из софтверной практики, названные рядом с ТРИЗ-проходом** (требование эвристического режима): speculative decoding, кэширование KV/промптов, каскады моделей (FrugalGPT-подобные), асинхронные очереди задач.
