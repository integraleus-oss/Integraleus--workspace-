## CRITICAL

**1. Recovery accepts an unauthenticated, disk-authored terminal status — the managed agent can declare its own SUCCEEDED.**
`scripts/execution-supervisor.py:246` — `recover()` short-circuits on `if state["status"] in TERMINAL:` *before* `managed_runner_alive()` (line 251) and before any terminal-evidence/nonce check (line 262). It then calls `notify_once` + `update_evidence` (lines 248-249) and returns 0. The run-loop deliberately refuses to trust disk status (the comment at `:221-222` says exactly that), but recovery has no equivalent guard.

Reached automatically: `projects/execution-supervisor-taskflow/index.js:322-324` skips a state file only when `status === "RUNNING"` *and* `lastVerified` is fresh. A state file whose `status` is anything else is reconciled immediately.

Failure scenario: the managed agent — which necessarily has write access to its own task root, since it is instructed to write `MANAGED_OUTCOME.json` there (`index.js:47,142`) — writes `{"status":"SUCCEEDED",...}` into `<taskRoot>/execution-supervisor-state.json`, preserving `flowId`/`sessionKey`/paths. Within one poll tick (5 s): `recover` accepts it, appends `exec-<runId>-succeeded` to the outbox, rewrites `EVIDENCE.md` to `Status: SUCCEEDED`; back in `index.js:276-277` every trust check passes (the admission record is genuine), `runtime.finish()` fires, and `adapter.sendText` reports `Execution supervisor: SUCCEEDED` to the owner. No RESULT.json, no nonce, no exit code, no runner exit was ever required. `validate_recovery_state` (`:65-76`) only checks filenames, not authenticity. The whole nonce/`contractValidated` apparatus is bypassed by not going through the run loop at all.

## HIGH

**2. `reconcileState` mutates before it validates trust.**
`projects/execution-supervisor-taskflow/index.js:271-277` — `python3 supervisor recover --state <path>` is spawned and awaited at line 271-272; the `untrusted supervisor state` check at line 276-277 runs only afterward. So the throw prevents the TaskFlow mutation and the notification but not the state finalization, outbox append, `EVIDENCE.md` rewrite, or the `os.killpg(int(state["pid"]), SIGTERM)` at `execution-supervisor.py:254`. Combined with finding 6, any attacker-writable path under the workspace becomes a same-uid `killpg` and file-write primitive driven by the exposed `execution_supervisor_recover` tool.

**3. Persisted originating delivery context is discarded and re-derived, so owner delivery is lost.**
`projects/execution-supervisor-taskflow/index.js:278-279` — reconcile overwrites `state.deliveryContext` with `deliveryFromDispatch({}, { sessionKey: state.sessionKey })`, ignoring the value the dispatcher persisted via `--delivery-json` (`index.js:209`, stored at `execution-supervisor.py:187`). That value is written but never read anywhere in the plugin.
Two concrete failures: (a) `deliveryFromDispatch` sources `accountId` from `ctx.accountId`, and the synthetic ctx has only `sessionKey`, so `accountId` is always `undefined` — on a multi-account channel `adapter.sendText` (line 296-299) targets the wrong account or fails; (b) for any session key not matching `:group:<n>:topic:<n>$` or `:direct:<n>$` — e.g. the `agent:main:main` private session exercised at `index.test.mjs:139` — both `channel` and `to` are `undefined`, so it falls back to `config.delivery`, and with `delivery` unset (it is optional, `openclaw.plugin.json:23`) line 293 throws `missing originating delivery context` on every 5 s tick forever. The correct routing was sitting in the state file the whole time. The owner is never notified.

**4. Heartbeat resurrects `RUNNING` over a terminal state and wipes `notificationId`, breaking exactly-once.**
`scripts/execution-supervisor.py:223-224` — under the finalize lock, the run loop unconditionally writes its in-memory dict (`status="RUNNING"`, `notificationId=None`) unless the persisted status is `TIMED_OUT` *and* monotonic `elapsed >= timeout` (line 217).
Failure scenario: the supervisor's timeout uses `time.monotonic()` (line 201/226) while `recover` uses wall clock against `startedAt` (`:252-253`). `CLOCK_MONOTONIC` excludes suspend time, so after a VM/laptop suspend the wall clock passes the deadline while monotonic has not. `lastVerified` is stale, so the recovery loop fires; `managed_runner_alive` is true; `recover` finalizes `TIMED_OUT`, appends `exec-<runId>-timed_out`, and SIGTERMs the process group (`:254-256`). The still-live supervisor's next heartbeat fails the line-217 guard (monotonic elapsed < timeout), rewrites `RUNNING`, and clears `notificationId`. It then observes the killed child and calls `finalize(..., "CRASHED", ...)`; `notify_once` (`:137`) builds `exec-<runId>-crashed`, which does not match the dedupe scan at `:142-148`, and appends a **second** outbox event. Two contradictory terminal events for one run.

**5. The terminal capability is persisted in plaintext and inherited by the model's process tree.**
`scripts/execution-supervisor.py:93-94` and `:102-104` require the raw `terminalNonce` to be echoed into the terminal-evidence file, which `index.js:141` places at `<taskRoot>/RESULT.json` — the same directory the agent is told to write `MANAGED_OUTCOME.json` into (`index.js:47,142`). Once the runner writes it, the forgery-prevention secret is a plaintext file the model can read, and rewriting that file with `terminalStatus: "SUCCEEDED"` plus the same nonce yields an accepted terminal claim (the run-loop check at `:207` reads the file after runner exit, but `recover` at `:262` reads it at any time once the runner is gone).
Additionally, `:191-197` publishes the nonce via `MANAGED_TERMINAL_FD` in `child_env` and an FD made inheritable by `pass_fds`. Both the env var and (absent explicit close/CLOEXEC in the runner) the descriptor propagate across `execve` to every descendant, including the model process. The supervisor provides no mechanism forcing the capability to be consumed and closed before the model starts; whether it leaks is left entirely to `managed-agent-runner.mjs`, which is outside this review's scope. A one-way channel (supervisor-signed token verified out of band) would not have this property.

**6. `safePath` does not canonicalize the target, permitting symlink escape.**
`projects/execution-supervisor-taskflow/index.js:60-65` — `realpath` is applied to `root` but the requested path only goes through `resolve()`, so `startsWith(canonicalRoot + "/")` is evaluated on the un-canonicalized path. A symlink created inside the workspace (`<workspace>/x/execution-supervisor-state.json → /elsewhere/execution-supervisor-state.json`) passes. `validate_recovery_state` (`execution-supervisor.py:65-76`) then computes `root = state_path.resolve().parent`, i.e. the *escaped* directory, and every sibling check trivially holds — so `recover` proceeds to write `EVIDENCE.md` and `outbox.jsonl` into an arbitrary same-uid directory and may `killpg` an arbitrary pid (`:254`).
