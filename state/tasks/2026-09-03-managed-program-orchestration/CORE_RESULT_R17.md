## What holds up

- **Independent locked planning before execution** — `managed-agent-runner.mjs:124-158`: a separate planner session writes `${outcome}.locked-plan.json` under a fresh `planToken`, a second independent session must return `verdict:"PASS"` under its own token, the plan is SHA-256 pinned (`:141`), re-checked at every slice top (`:163`) and before the terminal review (`:209`), and `planErrors` (`:44-53`) forbids removing or retitling any locked id. `:197` additionally forbids slice 1 from being terminal, so a single exit-0 slice can never be `SUCCEEDED`.
- **Bounded continuation** — `:200-205` caps consecutive process failures at 3; the loop is additionally bounded by `MANAGED_MAX_SLICES` (`:104`, minimum 2) and by the wall-clock deadline (`:167-168`, `:185-186`).
- **Evidence discipline** — `evidenceErrors` (`:55-83`) requires each `PASSED` claim's artifact to carry the per-run `runToken`, resolve via `realpath` inside `MANAGED_WORKSPACE_ROOT` with a proper `/` separator check, be non-empty, post-date `evidenceStarted`, contain the run token in its bytes, hash-match, and be distinct by both canonical path and content hash (`:71-72`). Combined with the contract's "every package and gate PASSED" rule (`:40-46` in `managed-outcome-contract.mjs`), all locked items need distinct artifacts.
- **No secret exposed to the model** — the terminal nonce arrives on fd 3, is read and `closeSync`'d before any child spawn, and `MANAGED_TERMINAL_FD` is deleted from both `process.env` and `childEnv` (`:116-123`). The fake agent asserts this by exiting 97/98 (`test.mjs:49`), and every scenario asserts `terminalNonce === "test-nonce"`. This one is solid.
- **Malformed output fails safely** — `loadJson` swallows parse errors to `null`, `validateManagedOutcome(null)` returns invalid (`contract:17`), the whole validation block is wrapped in try/catch (`:191-195`), and `args.result` is unlinked at `:97` before anything runs, so a mid-run crash can never leave a stale `SUCCEEDED` behind.

## HIGH defects

**H1 — The owner objective itself is the only unpinned input to the terminal review.**
`scripts/managed-agent-runner.mjs:102` reads `args.prompt` once into memory; nothing ever digests it. But `scripts/managed-agent-runner.mjs:222` hands the terminal reviewers the *path* and tells them to "Read the owner task at `${args.prompt}`" — re-read from disk after the executing agent has had unrestricted write access to the workspace. The runner's own threat model demonstrably includes "the executing agent tampers with files the reviewer reads": that is exactly why the plan is pinned at `:141`/`:209` and the outcome and evidence get before/after digest comparison at `:212-213`/`:227`. The root document defining "the complete objective" is the one artifact left out of that scheme. An executing slice can rewrite `TASK_PACKET.md` to a narrow objective, and the reviewer's "For SUCCEEDED verify the complete objective" check is then performed against the narrowed text. The locked plan limits the blast radius (per-claim titles survive), but the completeness bar the reviewer applies is attacker-controlled.

**H2 — The runner's own log file is admissible evidence, and the runner mutates it after hashing it.**
`evidenceErrors` (`:65-79`) accepts any workspace-contained path; there is no exclusion of runner-owned control files. `args["agent-output"]` sits inside the workspace and, from slice 1 onward, contains the run token verbatim (`:199` serializes `attempts[].outcome` and `latestOutcome`; the model is told the token at `:176` and can place it anywhere in a `CONTINUE` outcome, which `evidenceErrors` never inspects). So in slice N+1 the model can hash `agent-output.json`, cite it as a gate artifact, and it passes every mechanical check at `:194` — exists, in-workspace, fresh mtime, token-bearing, hash-matched, distinct.

The sharper half is the ordering: validation runs at `:194`, then `:199` overwrites `agent-output.json` with the new slice's log. The evidence snapshot at `:213` and its re-check at `:227` are both taken *after* that overwrite, so they agree. Net effect: the bytes the runner hash-verified are not the bytes the terminal reviewer opens, and the divergence is invisible to the before/after invariant that protects every other artifact.

## Medium (context, not the basis for the verdict)

- `:227` re-verifies the outcome digest and evidence snapshot across the review window but *not* `planDigest`, which is only checked at `:209` before the reviewers spawn — an asymmetry in an otherwise consistent pattern.
- `:221-225` runs two reviewers with an identical prompt, agent, and model, differing only in output path and token. They are independent *processes*, not independent *judgments*; correlated failure is likely, and `test.mjs:95` sets `FAKE_REVIEW_VERDICT` globally, so the "both must PASS" and per-index token-matching logic at `:230` is never exercised with a single dissenting reviewer.
- `test.mjs:94` runs the crash path with `MANAGED_MAX_SLICES: "3"`, making the 3-consecutive-failure cap at `:203` indistinguishable from the slice cap — the retry bound is asserted only incidentally.
- `TASK_PACKET.md:26-34` has all nine acceptance boxes unchecked, and `TASK_PACKET.md:43-44` still reads "Current gate: R12 core and runtime reviews both returned FAIL" while `:3` declares `RUNNING_R14_COMPLETION`. The packet's own record of completion is stale. Separately, `TASK_PACKET.md:31` ("reconciled by supervisor") cannot be verified from the four files I was permitted to inspect — `scripts/execution-supervisor.py` was out of scope, so the consumer side of `terminalNonce`/`terminalStatus` is unchecked here.

## Verdict

**FAIL** — on H1 and H2. Both are integrity gaps in the evidence-and-review chain that the rest of the design goes to real lengths to close, and both sit directly on the `SUCCEEDED` path. Neither produces a false success from exit code 0 alone (that specific ZSR failure is genuinely blocked), but both degrade the terminal review from "verifies pinned artifacts against a pinned objective" to "verifies partly attacker-mutable inputs," which is the property the whole mechanism exists to guarantee.
