## Spec findings

**S1 (blocking) — attempt-2 targeted verification can never produce a contract-valid verdict.**
`trusted_review_builder.py:216` hard-codes `"expected_coverage_scope": "full"` for every attempt. For attempt 2 the same manifest sets `expected_review_mode: "targeted_verification"` (`:207`). The verdict schema's top-level `allOf` (`review-verdict.schema.json:489-528`) requires `coverage_scope == "targeted"` whenever `review_mode == "targeted_verification"`, while the validator (`validate_review_verdict.py:422-426`) requires `document.coverage_scope == manifest.expected_coverage_scope`. The two constraints are mutually exclusive: a reviewer emitting `"targeted"` fails the semantic binding check, and one emitting `"full"` fails JSON-schema validation. Either way `contract_valid` is false → `build_projection` raises `ProjectionError` (`review_projection.py:59-60`) → `live_review_cycle` `FAILED_ADMISSION` → `ESCALATED`. Every builder-driven attempt 2 dies before any decision. Fix is one line: derive `expected_coverage_scope` from `review_mode` (`"targeted"` for attempt 2, `"full"` for attempts 1 and 3).

**S2 (blocking for the packet's goal) — a first-attempt `R15` is routed into a Codex rework instead of the review-only leg.**
`managed_one_cycle.py:62-68` handles `REWORK` at `attempt < max_attempts` before the new `R15` branch at `:69`. In builder mode attempt 1 is always `initial_full`, so `_final_full_ok` (`orchestrator_policy.py:1122-1124`) is always false; a clean or nit-only attempt 1 therefore lands on `R15_NEED_FULL_REVIEW` (`:1312-1324`) and burns `final_full_used → 1`. The controller consumes the `REVIEW_ONLY_FULL` directive as a code-rework packet (`managed_policy_review.py:75-76`), launches Codex a second time, and attempt 2 then either raises `BuilderError("targeted verification requires open prior findings")` (`trusted_review_builder.py:288-289`) or reaches `R15` again with the budget already spent → `R16_FULL_REVIEW_EXHAUSTED` → `ESCALATED`. Net: the only sequence that can ever reach `R17_ACCEPT` is "attempt 1 reports a major/blocker finding". A correct first attempt cannot be accepted.

**S3 — the carried finding registry is the one policy input that crosses attempts unauthenticated.**
`local_orchestrator_runner.py:84-87,104,116` adds `registry-after.json` and `registry_digest_file`, and `production_cycle_cli.py:204,213` feeds that file straight into the next ledger. Nothing verifies it: `admit_live_review` checks `decision_digest_file` and `projection_digest` (`managed_policy_review.py:45-48`) but not `registry_digest_file`, and no call site compares `canonical_digest(registry_after)` against the `registry_digest_after` the decision already binds (`orchestrator_policy.py:410`). The values agree today because both call sites use identical inputs, but the digest-binding the packet requires ("bind every generated input with SHA-256 digests") is not enforced on this hop.

## Standards findings

**St1 — the `prior_attempts` carry is implemented twice and must stay in lockstep.** `trusted_review_builder.py:257-259` and `production_cycle_cli.py:205-207` both append `{attempt_epoch: attempt - 1, **last_decision}`. It is correct today only because the CLI deliberately stores `prior_attempts` *excluding* its own `last_decision`. Any one-sided edit yields either a dropped epoch or a duplicate one, and a duplicate trips `duplicate_prior_attempt_epoch` → `R01_BINDING` with no local diagnostic. One shared helper should own this.

**St2 — the runner recomputes a registry `decide()` already produced, outside `decide()`'s guards.** `local_orchestrator_runner.py:84-87` indexes `fixture["execution_report"]["subject"]["tree_digest"]` directly and runs before the fail-closed invariant check at `:88`. For a malformed execution report that `decide()` would have returned as a clean `R01_BINDING` escalation, this raises `KeyError`/`TypeError` and the run is reported as `local_orchestrator_run_error` instead of a policy decision.

**St3 — builder mode fabricates three identical review legs to satisfy list indexing.** `production_cycle_cli.py:139` builds `[{prompt_text}] * 3` and `:174` indexes `packet["reviews"][attempt - 1]`, though `leg` carries nothing but the prompt in builder mode. In legacy mode the same indexing means an `R15` at attempt 2 raises a bare `IndexError` rather than a named `PacketError` (fail-closed, but unnamed).

**St4 — carried-context type errors bypass the builder's error contract.** `trusted_review_builder.py:283` (`previous.get("finding_registry", {}).get(...)`) raises `AttributeError` on a non-dict registry, and `:259` (`**previous["last_decision"]`) raises `TypeError` on a non-mapping. Both end at `managed_one_cycle`'s blanket `except` → `ESCALATED`, so behaviour is safe, but neither surfaces as `BuilderError`.

**St5 — carried forward unchanged from the prior closure:** `capture_clean_baseline` still sits outside `run_managed_cycle`'s try (`production_cycle_cli.py:153`), so a dirty worktree surfaces as `ERROR`/exit 2 rather than a cycle result; basename-only gate allowlist (`:120`); gate env is full `os.environ` plus one variable (`:124`); seal chmod `0o444` is advisory against the same user; `state/tasks/2026-08-12-orchestrator-trusted-input-builder/EVIDENCE.md` and `TASK_PACKET.md` checklist items 8-10 are still open.
