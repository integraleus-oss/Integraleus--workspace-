# Чек-лист аудита экрана HMI

Порядок пунктов = порядок приоритета. Сначала то, что мешает заметить аварию, затем то, что мешает работать, затем единообразие и косметика. Если находок много, выдавай их именно в этом порядке — заказчику важно понимать, что чинить первым.

Формат находки: **что не так → какое правило нарушено → что конкретно сделать**. Не «палитра неудачная», а «работающий насос залит зелёным → зелёный расходуется на нормальное состояние, при этом цвет должен быть зарезервирован под сигнализацию → сделать заливку off-white `#F0F0F0` для работающего и серую `#808080` для остановленного».

---

## 1. Обнаружение отклонений (критично)

- [ ] Экран в нормальном режиме выглядит спокойным и преимущественно серым? Есть ли цветные пятна, не означающие тревогу?
- [ ] Цвета тревог (`#E22028`, `#EC8629`, `#F5E11B`, `#916AAD`) используются **только** для тревог?
- [ ] Заметна ли активная тревога с расстояния рабочего места, за 1–2 секунды?
- [ ] Состояние кодируется не только цветом, но и формой/заливкой/текстом?
- [ ] Несквитированные тревоги мигают, сквитированные — нет, но остаются видны?
- [ ] Пиктограмма тревоги стоит рядом с элементом-источником, а не только в журнале?
- [ ] Мигает ли что-нибудь, кроме несквитированных тревог? (Не должно.)
- [ ] Баннер тревог присутствует и не мигает фоном/текстом (мигает только рамка)?
- [ ] Приоритеты тревог визуально различимы между собой?
- [ ] Отложенные и подавленные тревоги имеют видимую индикацию у соответствующих объектов?

## 2. Контекст данных

- [ ] У ключевых параметров есть аналоговое представление (шкала), а не только число?
- [ ] На шкалах отмечены аварийные и предупредительные границы, уставка?
- [ ] У параметров, где важна динамика, есть тренд или спарклайн?
- [ ] Единицы измерения указаны везде, где величина не безразмерна и не очевидна?
- [ ] Число знаков после запятой соответствует реальной точности, а не «сколько отдал ПЛК»?
- [ ] Обрабатываются особые значения (NaN, бесконечность, переполнение, обрыв связи, недостоверность)?
- [ ] Рядом со шкалами есть цифровые значения, и расположены они одинаково по всему проекту?

## 3. Компоновка

- [ ] Потоки идут слева направо, пары вверх, конденсат вниз?
- [ ] Компоновка соответствует мысленной модели оператора, а не P&ID и не планировке цеха?
- [ ] Линии только горизонтальные и вертикальные, пересечения минимизированы?
- [ ] Связанное по смыслу сгруппировано, несвязанное — разнесено?
- [ ] Экран не перегружен и не пустует?
- [ ] Важное — в верхней левой области; неважное не занимает лучшие места?
- [ ] Вспомогательные элементы (подписи, статика) визуально приглушены относительно данных?
- [ ] Есть ли на экране элементы, которые можно удалить без потери смысла? (Удалить.)

## 4. Надписи и выравнивание

- [ ] Подписи расположены по единому правилу (слева/над для дисплеев, справа для чекбоксов и бинарных индикаторов)?
- [ ] Текстовые надписи выровнены по левому краю?
- [ ] Числа выровнены по правому краю, с одинаковым числом знаков у сравниваемых величин?
- [ ] Единицы измерения справа от значений и выровнены по левому краю в столбец?
- [ ] Нет центрирования вне таблиц, кнопок и заголовков графиков?
- [ ] Надписи не пересекаются линиями и другими объектами?
- [ ] Весь текст горизонтальный?
- [ ] Подписи используют язык оператора, а не только позиционные обозначения?
- [ ] Заголовок экрана на одном и том же месте на всех экранах?
- [ ] Оставлен ли запас места под перевод (если проект многоязычный)?

## 5. Типографика и цвет

- [ ] Один sans-serif шрифт на весь проект, базовый кегль 10 pt?
- [ ] Значения крупнее подписей и единиц измерения?
- [ ] Кегль соответствует дистанции просмотра (табло vs. рабочее место)?
- [ ] Текст тёмно-серый `#3F3F3F`, а не чёрный?
- [ ] Фон экрана `#E0E0E0` или эквивалентный светло-серый?
- [ ] Оборудование — только контур `#A0A0A4`, без заливки, без градиентов, без 3D?
- [ ] Нет фотографий и рендеров оборудования?
- [ ] Толщина линий: основные контуры 3 px, вторичные 1 px, точки измерения — штрихпунктир 1 px?
- [ ] Контраст достаточный, но не утомляющий за смену?

## 6. Управление и взаимодействие

- [ ] Зоны нажатия соответствуют способу ввода (кнопки управления ≥40×40 px, навигации ≥35×35 px)?
- [ ] Отступы: ≥4 px (мышь) / ≥10 px (сенсор); между кнопками управления 10 px; кнопки навигации плотно, 2 px?
- [ ] Кнопки управления визуально отличаются от кнопок навигации?
- [ ] Пуск и останов — раздельные кнопки, а не один переключатель?
- [ ] Ответственные команды требуют подтверждения?
- [ ] Ввод значения и его применение разделены?
- [ ] Недоступные элементы неактивны, а не скрыты?
- [ ] Опасные команды не соседствуют вплотную с безопасными?
- [ ] Текст кнопки описывает выполняемую команду, а не текущее состояние?
- [ ] Есть обратная связь на действие оператора, для долгих операций — индикация процесса?

## 7. Иерархия и навигация

- [ ] Экран соответствует своему уровню по составу информации?
- [ ] С экрана уровня 1 нельзя управлять процессом?
- [ ] Навигация присутствует на каждом экране и в одном и том же месте?
- [ ] Можно перемещаться, не зная иерархии наизусть?
- [ ] Кнопки навигации показывают наличие тревог на экранах за ними?
- [ ] Есть переходы на смежные по процессу узлы (в том числе через подписи стрелок потоков)?
- [ ] Фейсплейты не перекрывают относящиеся к ним элементы?
- [ ] Вкладка «Тревоги» фейсплейта — крайняя правая/нижняя, основная — крайняя левая/верхняя?

## 8. Единообразие по проекту

- [ ] Один и тот же параметр отображается одинаково на всех экранах?
- [ ] Одно и то же оборудование имеет одинаковую форму и размер везде?
- [ ] Одинаковые объекты расположены в одинаковых местах на однотипных экранах?
- [ ] Сокращения из единого утверждённого списка?
- [ ] Элементы выровнены по сетке, без смещений в 2–3 пикселя?
- [ ] Используется библиотека переиспользуемых объектов, а не копипаст?
- [ ] Имена элементов в проекте осмысленные?
- [ ] У экранов есть версии и идентификаторы?

## 9. Производительность

- [ ] Частота обновления экрана вдвое выше частоты обновления данных?
- [ ] Переключение на экраны уровней 2–3 ≤ 2 с, уровней 1 и 4 ≤ 5 с?
- [ ] Реакция на действие пользователя в диапазоне 0.5–2 с?
- [ ] Нет мерцания из-за чрезмерной частоты обновления?

## 10. Проверка с людьми

Пункты, которые нельзя закрыть за столом, но без них аудит неполон:

- [ ] Дизайн проверялся **на рабочем месте** при реальном освещении и с реальной дистанции?
- [ ] Операторы участвовали в оценке прототипов?
- [ ] Подписи соответствуют тому, как операторы сами называют оборудование?
- [ ] Проверено восприятие при возможных нарушениях цветовосприятия?
- [ ] Проверено поведение экрана в аварийном режиме, а не только в нормальном?
