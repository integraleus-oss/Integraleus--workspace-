# Alpha BPR - меню и рабочие процедуры

Статус: черновик пользовательской инструкции, 2026-07-21.

## Назначение

Документ описывает текущие меню Alpha BPR HMI/BFF product trial и действия,
которые пользователь может выполнить внутри каждого меню.

Важно: это инструкция для текущего product trial. Часть экранов работает как
демонстрационный сценарий на подготовленных данных. Там, где действие не пишет
в live Alpha BPR API, это указано явно.

## Быстрый маршрут демонстрации

Рекомендуемый порядок показа:

1. `Библиотека рецептов`;
2. `Редактор процедур`;
3. `Формулы`;
4. `Согласование`;
5. `Версии и аудит`;
6. `Партии`;
7. `Ревью QA`.

## Статусы данных на экране

| Индикатор | Что означает |
| --- | --- |
| `Данные: сервер` | UI получил live данные от Alpha BPR API. |
| `Данные: trial` | Сервер доступен, но публичная поверхность показывает curated trial-набор. |
| `Данные: демо` | UI показывает fallback/evidence данные без live чтения нужной сущности. |

## Меню: Библиотека рецептов

### Для чего нужно

Это стартовый экран технолога и reviewer-а. Здесь выбирают мастер-рецепт,
смотрят его статус, операции, фазы, формулу, оборудование и связанные партии.

### Что видно

- список мастер-рецептов;
- фильтры `Все`, `Утверждённые`, `Черновики`, `На согласовании`;
- поиск по коду или названию;
- выбранный рецепт;
- операции и фазы ISA-88;
- формула и параметры;
- требования к оборудованию;
- карточки партий за смену.

### Основные действия

1. Найти рецепт через поиск или фильтр.
2. Выбрать рецепт в списке.
3. Нажать `ПРОЦЕДУРА`, чтобы перейти к редактору процедур.
4. Нажать `ФОРМУЛА`, чтобы перейти к редактору формулы.
5. Нажать `СРАВНИТЬ ВЕРСИИ`, если у рецепта есть версии для сравнения.
6. Нажать `УТВЕРДИТЬ` или `НА СОГЛАСОВАНИЕ`, если статус рецепта это допускает.
7. Нажать на карточку партии, чтобы открыть EBR.

### Текущая граница

В текущем public trial библиотека рецептов показывает curated trial-набор.
API доступен, но публичная workbench поверхность скрывает внутренние live
рецепты. Поэтому выбранные trial рецепты полезны для демонстрации workflow, но
не являются полноценным экраном live authoring.

## Меню: Создать рецепт

### Для чего нужно

Показать целевой сценарий создания новой процедуры: новый рецепт создаётся как
черновик, затем пользователь задаёт формулу, процедуру и отправляет на
согласование.

### Поля

- `Код рецепта` - короткий код, например `MR-PA6-02`.
- `Название` - человекочитаемое имя рецепта.
- `Размер партии` - плановый размер, например `2 000 кг`.
- `Оборудование` - аппарат или линия, например `MIX01`.
- `Шаблон` - стартовая структура: смешение/дозирование, реактор/выдержка или
  пустой черновик.
- `Автор` - пользовательская роль/учётка.
- `Причина создания` - обязательный контекст изменения.

### Процедура

1. Открыть `Библиотека рецептов`.
2. Нажать `+ СОЗДАТЬ РЕЦЕПТ`.
3. Заполнить карточку.
4. Нажать `Создать черновик`.
5. Перейти в `Далее: формула`.
6. Заполнить формулу.
7. Перейти в `Далее: процедура`.
8. Заполнить операции и фазы.
9. Перейти `К согласованию`.

### Текущая граница

Сейчас эта форма создаёт demo-черновик в браузере. Она не вызывает
`POST /api/recipes/`. Для live создания рецепта нужно использовать Swagger/API
или отдельный HMI/BFF сценарий `POST /api/demo/mvp-v0-1`.

## Меню: Редактор процедур

### Для чего нужно

Описать технологическую процедуру внутри рецепта: операции, фазы, оборудование,
длительности и критические точки.

### Что видно

- выбранный рецепт;
- список операций;
- фазы внутри операций;
- критичность фаз;
- сводка процедуры;
- поле `Причина изменения`;
- кнопка `СОХРАНИТЬ РЕВИЗИЮ`.

### Процедура редактирования

1. Выбрать рецепт.
2. Открыть `Редактор процедур`.
3. Изменить название операции или длительность.
4. Добавить операцию через `+ ДОБАВИТЬ ОПЕРАЦИЮ`.
5. Добавить или удалить фазу.
6. Отметить критичность фазы кликом по точке фазы.
7. Указать причину изменения.
8. Нажать `СОХРАНИТЬ РЕВИЗИЮ`.

### Что считается результатом

Целевой результат: новая ревизия рецепта с обновлёнными steps и audit reason.

### Текущая граница

Live HMI/BFF endpoint для сохранения процедуры существует:
`POST /api/demo/recipe-workbench/{recipeId}/procedure`. Но в текущем public
trial выбранные рецепты не имеют live `apiId`, поэтому изменение остаётся
демонстрационным на экране.

## Меню: Формулы

### Для чего нужно

Редактировать состав рецепта: компоненты, уставки, допуски и параметры процесса.

### Что видно

- выбранный рецепт;
- таблица компонентов и параметров;
- уставка;
- допуск;
- тип строки;
- проверки;
- поле причины изменения;
- кнопка `СОХРАНИТЬ РЕВИЗИЮ`.

### Процедура редактирования

1. Открыть `Формулы`.
2. Выбрать рецепт.
3. Изменить компонент, уставку или допуск.
4. При необходимости добавить строку через `+ ДОБАВИТЬ СТРОКУ`.
5. Выбрать тип строки:
   - `mat` - материал/компонент;
   - `par` - технологический параметр.
6. Проверить блок `Проверки`.
7. Указать причину изменения.
8. Нажать `СОХРАНИТЬ РЕВИЗИЮ`.

### Что считается результатом

Целевой результат: новая ревизия рецепта с обновлённой формулой и audit reason.

### Текущая граница

Live HMI/BFF endpoint для формулы существует:
`POST /api/demo/recipe-workbench/{recipeId}/formula`. В текущем public trial
сохранение остаётся экранным demo-действием, если выбранный рецепт не имеет
`apiId`.

## Меню: Согласование

### Для чего нужно

Показать очередь решений владельца: изменение рецепта, отклонение или выпуск
партии.

### Что видно

- очередь согласования;
- фильтры `Рецепты`, `Отклонения`, `Выпуск партий`;
- пакет решения владельца;
- проверки технологии, QA, валидации и аудита;
- журнал решения;
- действия `СРАВНИТЬ ВЕРСИИ`, `УТВЕРДИТЬ`, `ВЕРНУТЬ НА ДОРАБОТКУ`.

### Процедура согласования рецепта

1. Открыть `Согласование`.
2. Выбрать элемент в очереди.
3. Проверить код, версию, название и статус.
4. Проверить блок `Проверки владельцев`.
5. Открыть `СРАВНИТЬ ВЕРСИИ`.
6. Принять решение:
   - `УТВЕРДИТЬ`, если изменение принимается;
   - `ВЕРНУТЬ НА ДОРАБОТКУ`, если нужны правки.

### Текущая граница

Backend lifecycle работает через `submit-review`, `approve`, `return-review`,
`make-effective`. В текущем public trial очередь согласования в основном
curated. Live approve/return включается только для элементов с `apiId`.

## Меню: Версии и аудит

### Для чего нужно

Показать, что именно изменилось между версиями рецепта, и связать решение с
audit trail.

### Что видно

- сравнение старой и новой версии;
- количество изменённых, добавленных, удалённых и неизменённых строк;
- таблица diff;
- кнопка утверждения версии;
- пояснение, что batch EBR snapshots не меняются задним числом.

### Процедура просмотра diff

1. Открыть `Версии и аудит`.
2. Проверить левую и правую версии.
3. Просмотреть строки diff:
   - `без изм.`;
   - `изменено`;
   - `добавлено`;
   - `удалено`.
4. Если версия на согласовании и действие live-доступно, нажать `УТВЕРДИТЬ`.

### Текущая граница

Backend endpoints для versions/diff/audit существуют, но текущий public trial
возвращает curated diff. Это экран для объяснения workflow, а не полный live
audit explorer.

## Меню: Партии

### Для чего нужно

Открыть электронную запись партии: материалы, лоты, дозирование, очистка линии,
QA exceptions, snapshot рецепта и готовность к выпуску.

### Что видно

- идентификатор партии;
- рецепт и версия;
- frozen snapshot;
- материалы и лоты;
- коррекция по потенции;
- факт дозирования;
- line clearance;
- QA exceptions;
- release gates;
- кнопка `Печать / PDF`;
- статус готовности к выпуску.

### Процедура просмотра EBR

1. Открыть `Партии` или нажать карточку партии в библиотеке.
2. Проверить материалы и lot status.
3. Проверить расчёт коррекции по потенции.
4. Проверить факт дозирования и допуск.
5. Проверить line clearance.
6. Проверить QA exceptions.
7. Проверить snapshot рецепта.
8. Проверить release gates.
9. При необходимости нажать `Печать / PDF`.

### Текущая граница

Backend EBR/report API существует. Текущая integrated HMI вкладка показывает
встроенный trial/evidence batch-набор. Это не равно живой очереди всех партий
из `/api/batches`.

## Меню: Ревью QA

### Для чего нужно

QA проверяет электронную запись партии, исключения, дозирование, отчётные
артефакты и принимает решение о выпуске, удержании или отклонении.

### Что видно

- очередь QA;
- выбранная партия;
- гейты готовности к выпуску;
- дозирование;
- подпись QA;
- ревью аудита;
- кнопки `ОТКРЫТЬ ЭЗП`, `ОТЧЁТ PDF`, `ПОДПИСЬ QA`.

### Процедура QA review

1. Открыть `Ревью QA`.
2. Выбрать партию в очереди.
3. Проверить гейты.
4. Проверить дозирование.
5. Открыть ЭЗП.
6. Проверить отчётные артефакты.
7. Проверить audit review.
8. Принять решение QA.

### Текущая граница

`/api/demo/reviewer` читает состояние BFF/API и audit reviews live. Но EBR и
report dataset берутся из live batch только если в BFF state есть текущий
`batch_id`; иначе показывается evidence/fallback. Подпись QA в trial UI -
демонстрационная визуализация, не certified electronic signature.

## Live API процедуры вне верхнего меню

### Сквозной MVP v0.1 run

Endpoint `POST /api/demo/mvp-v0-1` выполняет полный live sandbox workflow:

1. создать product;
2. создать recipe draft;
3. внести revision;
4. submit-review;
5. approve;
6. make-effective;
7. создать order;
8. получить setpoints;
9. release order;
10. создать batch;
11. записать dose-record;
12. записать line-clearance;
13. start/complete batch;
14. record QA release;
15. получить EBR/report/audit evidence.

Это самый полный live API сценарий, но сейчас он не разложен как
пошаговый пользовательский мастер во всех вкладках integrated HMI.

### Операторский workflow

Отдельные HMI/BFF endpoints:

- `POST /api/demo/create-order`;
- `GET /api/demo/setpoints`;
- `POST /api/demo/release`;
- `POST /api/demo/plc-status`;
- `POST /api/demo/dose-record`;
- `GET /api/demo/report`;
- `POST /api/demo/cancel`.

Они используются для live demo workflow заказа/партии, но это отдельный
контур от текущей curated recipe workbench поверхности.

## Короткая честная формулировка для показа

Alpha BPR уже имеет рабочий backend lifecycle рецептов, партий, EBR, QA release
и audit evidence. Текущий HMI/BFF product trial показывает весь пользовательский
маршрут, но часть вкладок работает как curated/evidence demo. Полноценный
live-authoring через все меню ещё нужно достроить: прежде всего создание нового
рецепта из UI, live recipe cards с `apiId`, live партии в меню `Партии` и
чёткие badges `Live API / Trial / Evidence`.

## Не-заявления

Эта инструкция не является:

- производственным регламентом;
- UAT/go-live инструкцией;
- QMS/SOP;
- подтверждением Part 11 compliance;
- подтверждением certified electronic signatures;
- разрешением на customer plant integration.
