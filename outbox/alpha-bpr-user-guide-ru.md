# Руководство пользователя Alpha BPR

Статус: черновик руководства для демонстрационного стенда Home.

Alpha BPR - сервис управления мастер-рецептами, производственными заданиями,
электронной записью партии и доказательной отчетностью. На текущем стенде
операторский интерфейс открыт через HMI/BFF browser surface, пригодный для
публикации через Alpha.HMI.WebViewer. Alpha BPR не заменяет PLC/SCADA-контур:
PLC выполняет физическое дозирование и защитные функции, Alpha Platform
обеспечивает runtime/HMI/OPC UA/архивирование, а Alpha BPR хранит рецепты,
партии, evidence, аудит и отчеты.

## 1. Быстрый старт

Открыть интерфейс:

- из домашней сети: `https://192.168.68.125/alpha-bpr-hmi/`;
- через Tailscale: `https://100.114.189.16/alpha-bpr-hmi/`.

Если браузер показывает предупреждение о сертификате, это ожидаемо для
домашнего стенда с локальным/self-signed сертификатом. Для проверки можно
открыть "дополнительно" и продолжить.

Проверка готовности с сервера:

```bash
curl -fsS http://127.0.0.1:5088/health/ready \
  | jq -c '{status, historian:(.checks[] | select(.name=="historian") | .description)}'

curl -fsS http://127.0.0.1:5095/readyz \
  | jq -c '{status, bpr:.bpr.status, publicUrl}'

curl -fsS http://127.0.0.1:5095/api/demo/recipe-workbench \
  | jq -c '{source, recipes:(.recipes|length), batches:(.hmiBatches|length), approvalItems:(.approvalQueue.items|length), auditOk:.auditExport.ok}'
```

Ожидаемый результат для рабочего стенда:

- BPR API: `Healthy`;
- Historian: fresh / доступен;
- HMI/BFF: `ready`, BPR reachable;
- workbench: `source=live-api`.

## 2. Основные понятия

### Рецепт

Рецепт описывает, что производится, из каких компонентов, с какими уставками,
допусками, операциями, фазами, оборудованием и ограничениями по размеру партии.
В Alpha BPR рецепт является master object: его изменения должны проходить через
версию, причину изменения, аудит и согласование.

### Формула и компоненты

Формула - табличная часть рецепта. В ней есть:

- материалы / компоненты;
- технологические параметры;
- уставки;
- допуски;
- порядок строк.

Для материалов BPR использует дозы и допуски при расчете партии, EBR и
material balance.

### Процедура

Процедура описывает последовательность операций и фаз. Она не подменяет PLC:
физическое исполнение, блокировки, аварийные реакции, клапаны, насосы и
защитные функции остаются в PLC/SCADA. Alpha BPR хранит мастер-процедуру и
доказательную запись выполнения.

### Партия и EBR

Партия создается из конкретной версии рецепта. При старте партии Alpha BPR
фиксирует snapshot мастер-рецепта и рассчитывает scaled setpoints:

- `baseVolumeL` - базовый объем рецепта;
- `targetVolumeL` - целевой объем партии;
- `scaleFactor` - коэффициент масштабирования;
- scaled component doses - дозы компонентов для партии;
- material balance / yield - баланс и выход относительно scaled plan.

После создания партии изменения мастер-рецепта не меняют уже зафиксированный
batch snapshot.

### Статусы рецепта

В HMI используются русские статусы:

- `ЧЕРНОВИК` - можно редактировать формулу и процедуру;
- `СОГЛАСОВАНИЕ` - можно доработать до решения владельца;
- `УТВЕРЖДЁН` - read-only; используется для партий;
- `АРХИВ` / archive - не используется для новых партий.

Утвержденный рецепт нельзя менять напрямую. Для изменения нужно создать новую
редакцию/черновик и провести ее через согласование.

## 3. Роли

### Технолог

Работает с мастер-рецептами:

- создает или выбирает рецепт;
- редактирует формулу;
- редактирует процедуру;
- указывает причину изменения;
- отправляет рецепт на согласование.

### Владелец рецепта / Reviewer

Проверяет изменения:

- сравнивает версии;
- смотрит audit evidence;
- утверждает изменение;
- возвращает на доработку с причиной.

### Оператор

Работает с партиями:

- выбирает утвержденный рецепт;
- запускает партию;
- проверяет scaled setpoints;
- передает/контролирует исполнение через HMI/SCADA-контур;
- открывает EBR.

### QA

Закрывает доказательную часть:

- проверяет gates;
- смотрит dosing evidence;
- проверяет исключения;
- подтверждает готовность выпуска партии;
- использует EBR/report dataset как источник доказательств.

## 4. Навигация по интерфейсу

На главном экране 7 вкладок:

1. `Библиотека рецептов` - список рецептов, карточка выбранного рецепта,
   действия над рецептом.
2. `Редактор процедур` - операции, фазы, критичность, длительность.
3. `Формулы` - компоненты, параметры, уставки, допуски.
4. `Партии` - batch cards, EBR, scaled snapshot, material balance.
5. `Ревью QA` - гейты, дозирование, подписи, audit review.
6. `Версии и аудит` - сравнение версий и audit trail.
7. `Согласование` - очередь решений владельца, approve/return.

Если кнопка или чип не выполняет live-действие, интерфейс показывает пояснение.
Некоторые фильтры в демо-витрине пока переключают только визуальный режим.

## 5. Библиотека рецептов

### Найти рецепт

1. Откройте `Библиотека рецептов`.
2. Используйте поиск по коду или названию.
3. Используйте фильтры `Все`, `Утверждённые`, `Черновики`, `На согласовании`.
4. Выберите рецепт в левом списке.

В карточке отображаются:

- код и версия;
- статус;
- автор / дата изменения;
- формула;
- процедура;
- оборудование;
- scale summary, если доступен live backend;
- доступные действия.

### Отправить черновик на согласование

1. Выберите рецепт в статусе `ЧЕРНОВИК`.
2. Нажмите `НА СОГЛАСОВАНИЕ`.
3. HMI/BFF вызовет live API `submit-review`.
4. Рецепт перейдет в `СОГЛАСОВАНИЕ`.
5. Запись появится в аудите.

### Утвердить рецепт

1. Выберите рецепт в статусе `СОГЛАСОВАНИЕ`.
2. Нажмите `УТВЕРДИТЬ`.
3. HMI/BFF вызовет live API `approve`.
4. Рецепт станет `УТВЕРЖДЁН`.
5. После этого он становится read-only для прямого редактирования.

## 6. Редактирование формулы и компонентов

### Когда можно редактировать

Редактирование доступно только для рецептов:

- `ЧЕРНОВИК`;
- `СОГЛАСОВАНИЕ`.

Для `УТВЕРЖДЁН` интерфейс показывает read-only состояние. Это нормальное
поведение: утвержденный master recipe нельзя менять напрямую, чтобы не сломать
аудит и уже созданные batch snapshots.

На текущем Home стенде live-черновики можно найти через фильтр `Черновики`.

### Изменить компонент

1. Откройте `Формулы`.
2. В верхнем селекте выберите нужный рецепт.
3. Найдите строку компонента.
4. Измените:
   - название;
   - уставку;
   - допуск;
   - тип `материал` или `параметр`.
5. Укажите причину изменения в поле `Причина изменения`.
6. Нажмите `СОХРАНИТЬ РЕВИЗИЮ`.

После сохранения HMI/BFF отправляет изменение в Alpha BPR через live API,
перечитывает workbench и показывает обновленное состояние.

### Добавить компонент или параметр

1. Откройте `Формулы`.
2. Выберите редактируемый рецепт.
3. Нажмите `+ ДОБАВИТЬ СТРОКУ`.
4. Заполните название, уставку и допуск.
5. Выберите тип:
   - `материал` - участвует в component/dose logic;
   - `параметр` - технологический параметр процесса.
6. Укажите причину изменения.
7. Нажмите `СОХРАНИТЬ РЕВИЗИЮ`.

### Удалить или переставить строку

В строке формулы доступны кнопки:

- `↑` - поднять строку;
- `↓` - опустить строку;
- `×` - удалить строку.

После перестановки или удаления также нужно сохранить ревизию с причиной
изменения.

## 7. Редактирование процедуры

### Изменить операцию

1. Откройте `Редактор процедур`.
2. Выберите рецепт в статусе `ЧЕРНОВИК` или `СОГЛАСОВАНИЕ`.
3. Измените название операции, оборудование/unit или длительность.
4. Для фаз используйте поле `+ фаза (Enter)`.
5. Клик по маркеру фазы переключает критичность.
6. Укажите причину изменения.
7. Нажмите `СОХРАНИТЬ РЕВИЗИЮ`.

### Добавить или удалить операцию

- `+ ДОБАВИТЬ ОПЕРАЦИЮ` добавляет новую операцию.
- `↑` / `↓` меняют порядок операций.
- `×` удаляет операцию.

В процедуре должна остаться хотя бы одна операция.

## 8. Работа с партиями

### Запустить партию

1. В `Библиотека рецептов` выберите утвержденный рецепт.
2. Нажмите `ЗАПУСТИТЬ ПАРТИЮ`.
3. Alpha BPR создает order/batch и фиксирует snapshot рецепта.
4. Вкладка `Партии` показывает batch card.

Для демонстрационного стенда свежие batch cards поднимаются вверх.

### Проверить масштабирование партии

Откройте `Партии` и выберите batch card. В snapshot должны быть видны:

- `Base volume`;
- `Target volume`;
- `Scale factor`;
- scaled component doses.

Пример ожидаемого demo-сценария: `1000 л -> 2000 л`, `Scale factor ×2`.

### Проверить EBR

В EBR отображаются:

- recipe snapshot;
- dosing evidence;
- line clearance;
- QA exceptions;
- material balance / yield;
- readiness gates;
- report/print preview.

Material balance считается от scaled plan, а не от базовой рецептуры.

## 9. Ревью QA

Откройте `Ревью QA`.

Проверяются:

- готовность партии к выпуску;
- гейты evidence;
- дозирование и допуски;
- исключения QA;
- электронная подпись / signature rows;
- audit review.

Кнопка `ОТКРЫТЬ EBR` переводит к EBR выбранной партии. Кнопка `PDF ОТЧЁТ`
показывает демо-действие для report artifact. QA-подпись в текущем HMI связана
с готовностью партии к выпуску: если gates не пройдены, выпуск заблокирован.

## 10. Версии и аудит

Откройте `Версии и аудит`.

Здесь отображается live diff между версиями рецепта:

- неизмененные строки;
- измененные строки;
- добавленные строки;
- удаленные строки;
- статус версии;
- audit context.

Если новая версия находится на согласовании, ее можно утвердить из diff через
live API. Уже созданные batch snapshots от этого не меняются.

## 11. Согласование

Откройте `Согласование`.

Очередь показывает объекты, требующие решения владельца. Для live recipe items
доступны:

- `СРАВНИТЬ ВЕРСИИ`;
- `УТВЕРДИТЬ`;
- `ВЕРНУТЬ НА ДОРАБОТКУ`.

При возврате Alpha BPR переводит рецепт из `СОГЛАСОВАНИЕ` обратно в `ЧЕРНОВИК`
с причиной возврата. При утверждении рецепт становится `УТВЕРЖДЁН`.

Пакет решения владельца показывает:

- checks;
- audit record count;
- SHA-256 checksum audit export;
- последнее audit event.

## 12. Границы системы

Alpha BPR отвечает за:

- мастер-рецепты;
- версии и статусы рецептов;
- формулы, компоненты, параметры, допуски;
- production orders;
- batch snapshot;
- scaled setpoints;
- material balance / yield read model;
- EBR/report dataset;
- audit trail;
- approval workflow.

Alpha Platform / SCADA отвечает за:

- HMI/WebViewer runtime;
- OPC UA/Alpha.Server runtime;
- исторические значения через Alpha.Historian;
- операторскую визуализацию;
- alarm/trend surfaces, если соответствующие интеграции включены и проверены.

PLC отвечает за:

- физическое дозирование;
- interlocks;
- emergency stop;
- клапаны, насосы, мешалки;
- hard-real-time логику;
- закрытие дозы по flowmeter;
- защитные реакции на аварии.

## 13. Что пока является ограничением стенда

Текущий Home стенд уже показывает live vertical slice, но это не финальная
сертифицированная production-система.

Ограничения:

- часть фильтров в HMI пока демонстрационная;
- granular patch API для отдельных строк формулы/процедуры пока заменяется
  сохранением всего recipe payload;
- часть действий QA/reporting представлена как demo artifact;
- production-ready auth, электронная подпись, роли и WebViewer deployment
  требуют отдельной приемки;
- нативные Alpha.HMI экраны не являются текущим UI route; выбран browser
  surface через HMI/BFF/WebViewer.

## 14. Типовые проблемы

### Открывается старый вид

Обновите страницу с очисткой кэша или откройте в приватной вкладке. Корневой
URL должен отдавать integrated HMI с 7 вкладками.

### Рецепт не редактируется

Проверьте статус. `УТВЕРЖДЁН` открыт только для чтения. Для редактирования
выберите `ЧЕРНОВИК` / `СОГЛАСОВАНИЕ` или создайте новую ревизию.

### Кнопка сохранения просит причину изменения

Это ожидаемо. Причина нужна для audit trail. Заполните поле `Причина изменения`
и повторите сохранение.

### Workbench ушел в fallback

Проверьте:

```bash
curl -fsS http://127.0.0.1:5095/api/demo/recipe-workbench \
  | jq -c '{source,bff,recipes:(.recipes|length)}'
```

Ожидается `source=live-api`. Если не так, проверить HMI/BFF env, BPR API и
service logs.

### Historian stale / `/health/ready` unhealthy

Проверить:

```bash
curl -fsS http://127.0.0.1:5088/health/ready | jq .
systemctl is-active alpha.historian.server.service alpha.server.service
```

Для испытательного стенда допустим controlled reset Historian storage только
после явного решения владельца стенда.

## 15. Проверочный сценарий для демонстрации

1. Открыть `https://192.168.68.125/alpha-bpr-hmi/`.
2. Проверить, что видны 7 вкладок.
3. Открыть `Библиотека рецептов`, выбрать рецепт.
4. Открыть `Формулы`, выбрать черновик, изменить строку, указать причину,
   сохранить ревизию.
5. Открыть `Редактор процедур`, изменить операцию/фазу, указать причину,
   сохранить ревизию.
6. Отправить черновик на согласование.
7. Открыть `Согласование`, сравнить версии и утвердить или вернуть.
8. Открыть `Партии`, проверить Base/Target/Scale и material balance.
9. Открыть `Ревью QA`, проверить gates и dosing evidence.
10. Открыть `Версии и аудит`, проверить diff и audit context.
