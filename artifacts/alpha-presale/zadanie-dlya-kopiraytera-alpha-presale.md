# Задание для копирайтера: тексты интерфейса Alpha Presale

## Проверочный список

- [x] Используются только актуальные названия компонентов Alpha Platform
- [x] Запрещены устаревшие и выдуманные названия продуктов
- [x] Alpha Presale описан как внутреннее рабочее место пресейла, а не CRM и не лендинг
- [x] Запрошены практичные тексты для интерфейса: статусы, проверки, блокеры, подсказки и передача в расчёт

## Задание

Ты старший B2B-копирайтер для промышленной автоматизации, SCADA, АСУ ТП и пресейл-инструментов.

Твоя задача — подготовить тексты для веб-интерфейса продукта **Alpha Presale**.

## Контекст продукта

Alpha Presale — внутренний инструмент для подготовки исходных данных перед расчётом и подготовкой ТКП по Alpha Platform.

Это не CRM, не публичный сайт и не маркетинговая страница. Это рабочее место пресейла и инженера, где нужно быстро понять:

- что уже известно по проекту;
- каких данных не хватает;
- какие есть блокеры и риски;
- какая архитектура Alpha Platform предполагается;
- можно ли передавать кейс в расчёт;
- какие структурированные исходные данные нужны инженеру или специалисту по ТКП.

## Главная задача

Подготовить короткие интерфейсные тексты, которые помогают работать: заголовки, подписи, статусы, подсказки, пустые состояния, названия разделов, формулировки проверок, тексты блокеров и тексты для передачи в расчёт.

Тон: профессиональный, инженерный, спокойный, точный. Без рекламного пафоса. Не использовать формулировки вроде "революционная платформа", "единое окно цифровизации", "интеллектуальный подбор решения" и похожие маркетинговые клише.

## Запрещено

Не упоминай и не придумывай:

- Alpha MES
- Alpha ONE
- Alpha.Alarms 3.30
- standalone Alpha.Trends
- Alpha.Trends
- любые неуказанные модули Alpha
- реальные цены, SKU и коммерческие ставки
- финальный расчёт стоимости
- обещание, что система сама формирует финальное ТКП

Alpha Presale готовит структурированные исходные данные для расчёта, но не заменяет инженерную проверку и коммерческое согласование.

## Что нужно подготовить

Сделай набор коротких текстов для интерфейса.

### 1. Названия основных разделов

Подготовь названия для разделов:

- список заявок;
- обзор кейса;
- сбор вводных;
- архитектура;
- состав платформы;
- данные и теги;
- человеко-машинный интерфейс;
- архивы и отчёты;
- безопасность;
- блокеры;
- передача в расчёт.

### 2. Короткие описания разделов

Для каждого раздела дай описание в одну строку. Без маркетинга и общих фраз.

### 3. Статусы готовности

Подготовь короткие формулировки для статусов:

- готово;
- частично готово;
- требует уточнения;
- блокирует расчёт;
- принято для передачи в расчёт;
- возвращено на уточнение.

### 4. Тексты проверок полноты данных

Подготовь формулировки проверок:

- по количеству тегов;
- по резервированию;
- по клиентам и рабочим местам;
- по Alpha.HMI и Alpha.HMI.WebViewer;
- по тревогам и событиям через Alpha.HMI.Alarms;
- по графикам через alpha.hmi.charts;
- по архивированию через Alpha.Historian;
- по отчётам через Alpha.Reports;
- по безопасности через Alpha.Security;
- по сетевой архитектуре;
- по операционным системам и инфраструктуре.

### 5. Примеры блокеров

Сформулируй блокеры для ситуаций:

- нет количества тегов;
- не указано резервирование;
- неясно количество операторских мест;
- не определён веб-доступ;
- неясен объём архивирования;
- нет требований к отчётам;
- не описана модель доступа;
- не подтверждена целевая операционная система.

### 6. Тексты для блока передачи в расчёт

Подготовь формулировки для:

- краткой сводки проекта;
- списка принятых данных;
- списка открытых уточнений;
- факторов, влияющих на расчёт;
- блока "передать инженеру";
- блока "передать специалисту по ТКП";
- статуса готовности принятых исходных данных.

Если нужно упомянуть техническое имя артефакта, используй так: "принятые исходные данные (`accepted_presale_input`)". В пользовательских текстах по возможности используй русскую формулировку.

### 7. Тексты для кнопок и действий

Подготовь короткие тексты для действий:

- добавить вводные;
- отметить как проверенное;
- запросить уточнение;
- добавить блокер;
- сформировать передачу в расчёт;
- скопировать принятые исходные данные;
- передать в расчёт.

## Стиль формулировок

Пиши так, будто интерфейсом пользуется инженер-пресейл, которому важно быстро разобрать заявку.

Хорошо:

- "Не указано количество архивируемых сигналов"
- "Требуется уточнить схему резервирования Alpha.Server"
- "Данных достаточно для предварительной архитектурной оценки"
- "Передача в расчёт готова, но лицензирование требует проверки"

Плохо:

- "Откройте новые горизонты промышленной автоматизации"
- "Система автоматически рассчитала идеальное решение"
- "Интеллектуальный модуль сам подберёт конфигурацию"
- "Alpha MES обеспечит цифровую трансформацию"

## Формат результата

Выдай результат структурированно:

- `Разделы интерфейса`
- `Статусы`
- `Проверки полноты`
- `Блокеры`
- `Передача в расчёт`
- `Кнопки и действия`
- `Пустые состояния`
- `Предупреждения и ограничения`

Не делай длинные рекламные тексты. Нужны короткие формулировки, готовые к вставке в интерфейс.
