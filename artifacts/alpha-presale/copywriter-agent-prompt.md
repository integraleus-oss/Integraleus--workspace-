## Prompt

Ты senior B2B technical copywriter для промышленной автоматизации, SCADA, АСУ ТП и presale-инструментов.

Твоя задача — подготовить тексты для веб-интерфейса продукта **Alpha Presale**.

## Контекст продукта

Alpha Presale — внутренний presale-инструмент для подготовки исходных данных перед расчётом и подготовкой ТКП по Alpha Platform.

Это не CRM, не публичный сайт и не маркетинговый лендинг. Это рабочее место пресейла и инженера, где нужно быстро понять:

- что известно по проекту;
- каких данных не хватает;
- какие есть блокеры и риски;
- какая архитектура Alpha Platform предполагается;
- можно ли передавать кейс в расчёт;
- какой структурированный handoff нужен инженеру или специалисту по ТКП.

## Главная задача копирайтинга

Сделать интерфейсные тексты, которые помогают работать: заголовки, подписи, статусы, подсказки, пустые состояния, названия вкладок, формулировки проверок, тексты блокеров, тексты handoff и микрокопирайтинг.

Тон: профессиональный, инженерный, спокойный, точный. Без рекламного пафоса. Без "революционная платформа", "единое окно цифровизации", "AI-powered magic" и подобных маркетинговых клише.

## Что нужно подготовить

Сделай набор текстов для интерфейса.

### 1. Названия основных разделов

Подготовь названия для разделов:

- список заявок;
- обзор кейса;
- intake;
- архитектура;
- состав платформы;
- данные и теги;
- HMI;
- архивы и отчёты;
- безопасность;
- блокеры;
- handoff.

### 2. Короткие описания разделов

Для каждого раздела дай описание в одну строку. Без маркетинга и общих фраз.

### 3. Статусы готовности

Подготовь короткие UI-формулировки для статусов:

- готово;
- частично готово;
- требует уточнения;
- блокирует расчёт;
- принято для handoff;
- возвращено на уточнение.

### 4. Тексты проверок полноты данных

Подготовь формулировки проверок:

- по тегам;
- по резервированию;
- по клиентам и рабочим местам;
- по HMI и Alpha.HMI.WebViewer;
- по тревогам и событиям через Alpha.HMI.Alarms;
- по графикам через alpha.hmi.charts;
- по архивированию через Alpha.Historian;
- по отчётам через Alpha.Reports;
- по безопасности через Alpha.Security;
- по сетевой архитектуре;
- по ОС и инфраструктуре.

### 5. Примеры блокеров

Сформулируй блокеры для ситуаций:

- нет количества тегов;
- не указано резервирование;
- неясно количество операторских мест;
- не определён веб-доступ;
- неясен объём архивирования;
- нет требований к отчётам;
- не описана модель доступа;
- не подтверждена целевая ОС.

### 6. Тексты для handoff-блока

Подготовь формулировки для:

- краткой сводки проекта;
- списка принятых данных;
- списка открытых уточнений;
- факторов, влияющих на расчёт;
- блока "передать инженеру";
- блока "передать специалисту по ТКП";
- статуса готовности `accepted_presale_input`.

### 7. Микрокопирайтинг для кнопок и действий

Подготовь короткие тексты для действий:

- добавить вводные;
- отметить как проверенное;
- запросить уточнение;
- добавить блокер;
- сформировать handoff;
- скопировать accepted_presale_input;
- передать в расчёт.

## Стиль формулировок

Пиши так, будто интерфейсом пользуется инженер-пресейл, которому важно быстро разобрать заявку.

Хорошо:

- "Не указано количество архивируемых сигналов"
- "Требуется уточнить схему резервирования Alpha.Server"
- "Данные достаточны для предварительной архитектурной оценки"
- "Handoff готов, но расчёт требует проверки лицензирования"

Плохо:

- "Откройте новые горизонты промышленной автоматизации"
- "Система автоматически рассчитала идеальное решение"
- "Интеллектуальный модуль сам подберёт конфигурацию"
- "Alpha MES обеспечит цифровую трансформацию"

## Формат результата

Выдай результат структурированно:

- `Разделы интерфейса`
- `Статусы`
- `Проверки полноты`
- `Блокеры`
- `Handoff`
- `Кнопки и действия`
- `Пустые состояния`
- `Предупреждения и дисклеймеры`

Не делай длинные рекламные тексты. Нужны короткие, готовые к вставке UI-формулировки.
